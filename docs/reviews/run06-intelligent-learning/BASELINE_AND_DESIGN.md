# Run06 baseline and design contract

Build from complete approved Run05 commit7615804 (implementation8ddb482), not Run04/main4b255cb. Run05 working tree was clean; backup checksums and independent-restore receipt were verified. Preserve its branch/history and all learner state. No production promotion is authorized.

The established learning studio remains the reference: editorial serif headings, navy#102d46, teal#146981, mint#def4e8 and current system/DM Sans fallbacks. Read Screen and Ask a question form one compact support rail near the lesson title, with secondary settings in native disclosures. Existing Trainer Narration remains distinct and keeps its18approved recordings/transcripts. No homepage controls or new course families.

Read Aloud uses native Web Speech progressive enhancement. Controlled DOM extraction excludes navigation, hidden content, feedback not yet revealed, drafts and model-answer data. Reading focus is paragraph/section-level; no promised word synchronization. All speech is user-initiated. Mode, pause/resume/restart/stop, speed and voice controls use the same44px touch/focus treatment. Stop on navigation/backgrounding; recorded audio and TTS are mutually exclusive. Unsupported/no-voice/error states remain honest.

The tutor opens an attached desktop panel or mobile full-height sheet with contextual lesson/screen label, suggested prompts, explicit source references and ephemeral conversation. The panel traps focus and restores the trigger on close; Escape closes it. It does not modify learning progress or automatically ingest drafts. The static preview cannot contact the Mac directly. A separate loopback HTTPS local pilot serves the static build plus a bounded authenticated /api/tutor contract. No tunnel, public runtime exposure, paid inference or new cloud service is configured. Future remote access is a separately approved deployment boundary.

Motion is limited to150msstate/background transitions and disabled under reduced motion. No avatars/decorative animation. Desktop/tablet/mobile and keyboard/automated accessibility evidence are separate from owner visual acceptance and native screen-reader/physical-device acceptance.
