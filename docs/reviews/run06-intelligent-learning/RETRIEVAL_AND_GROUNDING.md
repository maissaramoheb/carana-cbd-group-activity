# Authorized retrieval and provider contract

62 teaching records: all56 approved digital learning screens and6 manually curated paraphrases of inspected official lesson-plan teaching pages. Original official PDFs remain in the verified Run02 References backup; six paraphrases identify exact supplied filenames, SHA256, page and teaching-only provenance. No answer-key/facilitator Annex D ingestion. Approved digital adaptations are labelled as adaptations; their referenced official page metadata does not imply verbatim official text. Index includes original source-file hashes.

Index builder explicitly allowlists lead/points/takeaway/visible conceptual explanations and narration scripts. It excludes quizzes, decision answers/feedback, classification keys, microcase model answers, applied-tool examples, learner drafts and browser state. knowledge.json is backend-only. Rebuild with npm run tutor:index after an approved teaching-source change; compare provenance before accepting it.

Retrieval validates exact lessonId/screenId/mode, tokenizes/stems simple English terms and uses inverse document frequency plus title/body weighting. Context boosts current screen for generic actions; specific questions can retrieve across lessons. A weighted coverage threshold rejects weak keyword overlaps instead of treating any mention of police as supporting an unrelated claim. Top3 passages, each max2100characters, are supplied as quoted untrusted JSON. This is a small full-text corpus, not a vector database. No embedding downloads or database dependency.

Provider receives model/question/passages/signal; emits answer/example/uncertainty/sourceIds plus deterministic source metadata and metrics. Temperature0, thinkfalse, JSON schema, bounded tokens. Model IDs must be in the retrieved set; official page numbers/URLs invented in model prose and numeric curriculum claims absent from evidence fail closed. References are always rendered from the retrieval catalog, never model-created pages. Examples are visibly invented and separate from curriculum assertions. Unknown content returns an evidence-limit explanation. Syntax and numeric checks cannot establish semantic entailment of every sentence.

The current UI displays lesson number/title, section and screen. It sends only metadata IDs to authoritative server retrieval; screen text and private drafts are not automatically sent. Deliberate selected teaching passages become the user's visible question; detected private draft selections have no Ask AI action. Active checkpoint mode always returns study guidance; no progress or checkpoint writes occur.

Contract: GET /api/tutor/status returns availability/provider/model/local-pilot/requiresAccess. POST /api/tutor requires HTTPS same-origin plus Bearer access and JSON {question,context:{lessonId,screenId,mode}}. Validated NDJSON events are content followed by done {kind,provider,model?,sources}. Status401/403/413/415/429/503 reflect access/origin/limits/unavailability. No source text, pilot credential or provider URL is embedded in browser configuration. Future provider replacement is confined to server provider/configuration; UI contract and course state need no redesign.
